# ARMMATE — Your friend in Armenia.

A responsive Armenian, Russian and English website for a personal travel assistance service in Armenia. The primary service is a personal local assistant over WhatsApp or Telegram. In-person companionship is optional and agreed separately. Every customer receives an individual offer; there are no fixed packages, public prices or automatic price calculations.

**Live site:** https://armmate.am/

**What is Armmate?** Armmate is a personal tourist assistance service in Armenia: local recommendations, travel organisation and a local assistant on WhatsApp or Telegram. Optional in-person companionship and individual pricing are agreed personally. Read the [official business overview](https://armmate.am/en/about-armmate/) or [contact Armmate](https://armmate.am/en/contact/).

**Business specification:** [docs/BUSINESS_CONCEPT.md](docs/BUSINESS_CONCEPT.md)

**Brand and logo:** [docs/BRAND.md](docs/BRAND.md). Slogan: “Քո ընկերը Հայաստանում։ / Твой друг в Армении. / Your friend in Armenia.”

## Run locally

The website serves committed static files and has no runtime dependencies. To preview it with Python 3:

```sh
python scripts/serve.py
```

Open http://127.0.0.1:4187. Armenian is at `/`, Russian at `/ru/`, and English at `/en/`. Each URL contains the complete translated HTML, including without JavaScript. Legacy `?lang=hy|ru|en` links still work with JavaScript. The original `#plan` anchor leads to direct contact links.

The sitemap includes 36 canonical pages: three homepages, three business-overview pages, nine service/contact pages, three independent-travel planning guides and 18 destination guides. Routes live in `seo.js`; business identity content is in `scripts/brand-content.cjs`, service content in `scripts/search-content.cjs` and guide content in `scripts/guide-content.cjs`.

## Direct business contacts

The owner-supplied contacts are WhatsApp at **+374 91 110799**, Telegram **@armmate_support**, and **armmate.support@gmail.com**. `site-config.js` generates the three destinations everywhere on the website.

The contact section contains `https://wa.me/37491110799`, `https://t.me/armmate_support` and `mailto:armmate.support@gmail.com`. These are ordinary links in the initial HTML and work without JavaScript. Email opens the visitor's preferred email app. Replace WhatsApp's working phone link only with the actual short link generated by the owner's WhatsApp Business account.

A compact button stays in the bottom-right corner and expands to the same three contact links. The native disclosure works without JavaScript; JavaScript adds Escape, outside-click and focus-leaving dismissal. Both contact locations use `site-config.js`.

There is no enquiry form, generated draft, clipboard/download workflow, booking or online payment. Visitors choose WhatsApp, Telegram or email and write their own message. Requirements, prices and terms are discussed personally. No message is sent automatically. Automated checks inspect the destinations without contacting recipients.

The website stores only the language preference in local storage. Public contact configuration must never contain passwords or credentials.

## Checks

Node.js 22+ is used for development checks only:

```sh
npm ci
npx playwright install chromium
npm test
npm run check:generated
npm run audit:site
npm run check:format
```

The browser suite checks all three translations, pricing rules, direct contact links, experience-to-contact navigation, mobile navigation, responsive layout and photo credits. It does not contact messenger recipients. Use `npm run format` after edits.

It also checks the complete HTML without JavaScript, canonical/hreflang consistency, JSON-LD against visible FAQs, legacy language URLs, sitemap destinations, optimized fonts and the noindex error page. After editing layout, translations, contacts or SEO metadata, run `npm run build` and commit the generated pages. ## Publishing and collaboration

GitHub Pages serves the `main` branch from `/`. `.nojekyll` keeps the site static. Merging or pushing reviewed changes to `main` triggers the existing Pages deployment. There is no paid hosting dependency.

See [CONTRIBUTING.md](CONTRIBUTING.md) for the development workflow and [docs/LAUNCH_CHECKLIST.md](docs/LAUNCH_CHECKLIST.md) for the remaining operational decisions.

Search account setup is in [docs/SEARCH-SETUP.md](docs/SEARCH-SETUP.md). After publishing new or changed pages, `npm run notify:yandex` submits the canonical sitemap URLs through Yandex's IndexNow endpoint. For subsequent small updates, pass only the changed paths, for example `npm run notify:yandex -- /ru/kontakty/`. This is an indexing notification, not a ranking or inclusion guarantee. It is never run by normal builds or tests.
